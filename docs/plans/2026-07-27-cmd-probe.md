# Cmd Probe for Node Liveness

## Context

The routing matcher system (`Host`, `Path`, `ClientIP`, etc.) is entirely
static — no way to make dynamic decisions like "route to node A only during
business hours" or "check external conditions before selecting this node."

Original idea: add a `Cmd` matcher to the routing rule engine, running a shell
command per-request. That fails because `Match()` is on the hot path (every
connection, every node candidate) — per-request `fork + exec` is a non-starter.

The right home is the existing [node-liveness-probe plan](node-liveness-probe.md):
add a `cmd` probe type. Periodic control-plane check, not per-request
data-plane check.

## Design

Add a `"cmd"` probe type to the node liveness probe system. The probe runs a
user-provided command on the configured interval; exit 0 = healthy, non-zero
(including timeout) = mark dead.

```
probeNode → cmd probe → exec sh -c <command>
                │
        exit 0 → node.Marker().Reset() + SetProbeResult(ok)
        exit ≠0 → node.Marker().Mark()  + SetProbeResult(fail)
                │
        FailFilter skips marked nodes in hop selector
```

This reuses the **entire existing pipeline** — `FailFilter`,
`LowestLatencyStrategy`, `LatencyFilter`, goroutine lifecycle (`Close()`
cascade on reload) — with zero new infrastructure.

## Config

```yaml
hops:
- name: hop-1
  nodes:
  - name: biz-hours
    addr: proxy1:1080
    probe:
      type: cmd
      command: 'test $(date +%H) -ge 9 -a $(date +%H) -lt 18'  # 9am-6pm only
      interval: 30s
      timeout: 5s
  - name: with-check
    addr: proxy2:1080
    probe:
      type: cmd
      command: './scripts/health-check.sh'
      interval: 60s
      timeout: 10s
```

`ProbeConfig` gains a `Command` field. When `type: cmd` is specified, the
probe goroutine shells out to `sh -c <command>` instead of doing TCP/HTTP
dial.

## CmdProber

```go
package probe

import (
    "context"
    "fmt"
    "os/exec"
    "time"
)

type CmdProber struct {
    Command string
    Timeout time.Duration
}

func (p *CmdProber) Probe() error {
    ctx, cancel := context.WithTimeout(context.Background(), p.Timeout)
    defer cancel()
    cmd := exec.CommandContext(ctx, "sh", "-c", p.Command)
    if err := cmd.Run(); err != nil {
        return fmt.Errorf("cmd probe: %w", err)
    }
    return nil
}
```

No env vars needed — the command runs periodically, not per-request.

## Implementation

| File | Change |
|------|--------|
| `core/chain/probe.go` | `ProbeConfig` + `Command` field, `ProbeTypeCmd` constant |
| `x/internal/probe/cmd.go` | **NEW** — `CmdProber` struct + `Probe()` method |
| `x/chain/node.go` (`probeNode` func) | Add `case chain.ProbeTypeCmd:` dispatch |
| `x/config/config.go` | `ProbeConfig` + `Command` field |

All other changes (goroutine lifecycle, marker integration, `FailFilter`,
`LowestLatencyStrategy`, `LatencyFilter`, `Close()` cascade) come from the
liveness probe plan with zero modification.

## Security

- Commands run as the same user as gost — no privilege escalation
- Config files are already trusted input (they can specify arbitrary
  listeners, dialers, plugin binaries)
- Users who don't want this simply don't use `type: cmd`

## Skipped

- Per-request `Cmd` matcher in routing rules — wrong hot-path fit,
  `exec` belongs on the control plane
